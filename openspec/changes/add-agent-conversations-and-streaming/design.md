# Design

## Context

变更动机见 `proposal.md`，行为契约见 `specs/agent-configuration/spec.md` 与 `specs/conversation-streaming/spec.md`。当前系统是 Vue 3 + Spring Boot 3 + Java 17 单体应用，Bearer JWT 保存在 `sessionStorage`；服务端根据令牌用户重新读取数据库中的最新角色和 `class_id`。第 4 课已经提供异步材料解析、MySQL/Qdrant 混合检索、非流式 `ChatGateway`、`/api/ask` 和可追溯引用。

V1 已创建简化的 `assistants(id, class_id, name)` 与 `skills(id, assistant_id, class_id, name)`。它们由演示种子使用，但尚无管理 API、独立技能模型、会话或消息。前端已有 `AppShell`、统一设计令牌、GPT 风格知识检索页及 `materialId + chunkId` 引用上下文。Nginx 目前对所有 `/api/` 使用同一代理配置并采用默认缓冲。

本次必须演进现有模型并保留既有标识和种子数据，不能另建一套重复的智能体表。新链路需要长连接和远程模型流，但班级、资源归属和配置读取仍以 MySQL 为权威；上传内容、模型输出和客户端控制字段均不可信。

## Goals / Non-Goals

**Goals:**

- 以可回滚的 V5 migration 把既有智能体/技能演进为可配置、多对多且可持久化会话的模型。
- 让智能体配置、技能解析、会话归属和每轮绑定读取共享服务端角色与班级边界。
- 在复用既有混合检索的前提下增加材料白名单，并用确定性路由和固定消息组装得到可测试结果。
- 通过真正的上游流式调用和 SSE 逐帧输出，明确首帧前、首帧后、部分正文和持久化失败的不同语义。
- 复用现有应用壳、引用上下文与网关配置，并让 OpenAPI 成为后端接口说明的可执行入口。

**Non-Goals:**

- 不把会话服务拆成微服务，也不增加消息队列、WebSocket 或新的认证状态。
- 不引入通用 Agent 框架、模型自主工具调用、语义技能路由或多技能协作。
- 不改变已有 `/api/ask`、材料索引、切片、RRF、引用编号与上下文接口契约。
- 不承诺多个节点同时生成同一会话轮次；首版只禁止同一浏览器重复提交并保证数据库归属安全。

## Decisions

### Decision 1: 用 V5 原地演进现有智能体和技能表

新增一个 Flyway migration，保持 `assistants.id`、`class_id` 和 `name`，并增加 `prompt_text`、`enabled`、创建/更新时间及 `(class_id, name)` 唯一约束。`skills` 保持原 ID、班级和名称，增加触发词、资料范围、工具、启用状态、说明、原始文本和时间字段；迁移先用兼容默认值补齐旧行，再创建新的非空及唯一约束。

关联和会话模型如下：

| 表 | 关键字段与约束 |
| --- | --- |
| `assistant_skills` | `assistant_id + skill_id` 联合主键，两端删除级联；应用层与迁移保证同班 |
| `assistant_materials` | `assistant_id + material_id` 联合主键，两端删除级联；应用层与迁移保证同班 |
| `conversations` | `class_id`、`user_id`、`assistant_id`、标题、时间；为用户列表建立 `(user_id, class_id, updated_at)` 索引 |
| `messages` | `conversation_id`、`role`、正文、可空 `skill_name`、引用 JSON、完成状态、时间；按 `(conversation_id, id)` 排序 |

迁移在删除 `skills.assistant_id` 前，先把原有关系复制到 `assistant_skills`。既有技能使用安全且可编辑的默认触发词、说明与原始文本，工具固定为 `knowledge_search`，不猜测材料绑定；既有智能体默认启用。`DemoDataInitializer` 改为按班级和名称幂等补齐配置，不依赖固定自增 ID，也不覆盖教师已经编辑的数据。

消息引用保存为当前回答的展示快照，包括连续编号、材料/切片标识、标题、切片序号和摘录。这样材料标题或索引以后变化时历史仍可读；打开上下文时仍以当前班级重新授权，快照不能充当访问凭据。部分失败的助手消息使用明确状态 `FAILED`，完成消息使用 `COMPLETED`，避免把截断正文伪装成完整回答。

选择理由：原地演进能保留已有外键与演示数据。备选是新建 `tutor_agents` 和新技能表，但会制造双份事实源、重复种子及后续迁移歧义；把绑定序列化进智能体 JSON 又无法用外键阻止悬空引用。

### Decision 2: 配置 API 使用完整替换和事务内预校验

后端增加以下资源型接口，最终 DTO 名称可按项目惯例调整，但路由和权限保持稳定：

```text
GET/POST        /api/assistants
GET/PUT         /api/assistants/{id}
GET/POST        /api/skills
GET/PUT/DELETE  /api/skills/{id}
GET/POST        /api/conversations
GET             /api/conversations/{id}
POST            /api/conversations/{id}/messages  -> text/event-stream
```

智能体写请求提交完整的字段、技能 ID 集和材料 ID 集。服务在同一事务中先以当前 `class_id` 批量加载全部引用并比较数量，通过后才保存主体并原子替换绑定；任何缺失、跨班、重复名称或字段错误都不产生部分更新。技能先在纯解析器中完整校验，再进入事务创建或覆盖结构化字段与原文。删除技能只级联绑定，不删除智能体和会话。

所有 Controller 都通过 `CurrentUserService` 获取数据库中的最新用户。Repository 对单资源使用 `id + classId`，会话进一步使用 `id + userId + classId`；教师写权限在服务端校验，学生看不到控件只是体验优化。未经认证为 401，角色越权为 403，按 ID 访问不存在、跨班或不可见资源统一为 404。

选择理由：完整替换让编辑页面和事务边界清楚，也避免增删多个绑定端点产生中间状态。备选的绑定增量接口会增加竞态、回滚和客户端同步复杂度，本课不需要。

### Decision 3: 技能原文使用严格、确定性的服务端解析器

技能创建和编辑均接收 UTF-8 JSON 字符串 `sourceText`，不新增 multipart 文件存储。解析器按 Unicode code point 计数，以第一个空行分隔元数据和正文；元数据逐行解析 `字段：值`，忽略注释和纯空白，并拒绝重复/未知字段。触发词按中英文逗号、顿号、分号与竖线切分，去空白、忽略空词并保持首次出现顺序。`工具` 若存在只能是 `knowledge_search`，最终数据库也只保存该值。

原文与解析字段同时保存，返回编辑页时使用原文，路由和检索只使用结构化字段。解析错误映射为稳定字段和面向教师的 400 文案，不回显堆栈或数据库约束文本。

选择理由：保留原文方便教学场景直接编辑，结构化字段保证执行可预测。备选是在浏览器解析后提交字段，但客户端规则可被绕过且会产生多套解析结果；上传实体文件会引入没有必要的文件生命周期。

### Decision 4: 会话锁定智能体，回答轮次读取当前绑定快照

创建会话时只接受 `assistantId`，服务端验证其为本班已启用智能体并写入会话。之后消息接口不接受智能体、班级、技能、材料或系统消息覆盖值。智能体停用只影响新会话；已有会话仍按锁定 ID 工作。

每轮在发送任何 SSE 帧前完成：会话归属校验、问题校验、智能体读取、当前技能/材料绑定读取、技能路由、用户消息与首轮标题提交、限定检索及上游流式连接建立。该时点取得的配置和引用组成不可变的“本轮快照”，流开始后教师修改配置只影响下一轮。用户消息先在短事务中提交，因此后续检索或连接失败仍可审计；助手消息在结束时由独立事务保存。

历史窗口从本轮用户消息之前的有效消息中选最近 6 条，再按写入顺序组装，每条截断为 500 个 code point；当前问题单独加入，避免把刚保存的问题重复两次。历史中的 `FAILED` 助手正文可展示但不进入模型窗口，空正文和非法角色永不进入 prompt。

选择理由：每轮快照兼顾“绑定下一轮即时生效”和单轮输出稳定。备选在会话创建时永久复制绑定会违背教师更新配置的需求；每个 delta 重新查询绑定既昂贵又会让同一回答前后规则变化。

### Decision 5: 技能路由和材料限定均在可信服务端完成

路由器只接收本轮快照中已启用、同班且已绑定技能。问题与触发词使用 `Locale.ROOT` 大小写归一化；每个不同关键词命中子串得 1 分，最高正分胜出，同分按技能 ID 升序，零分返回空。名称包含“解题引导”时追加服务端硬约束，技能正文不能覆盖该约束。

扩展 `RetrievalService` 的内部入口，使其接收服务端生成的 `allowedMaterialIds`；现有公开检索与 `/api/ask` 继续使用原入口。空白名单直接返回空，不查询全班。关键字 SQL、Qdrant filter 后的 MySQL 回表以及最终候选都同时校验当前班级、READY 状态和材料白名单。若选中技能有资料范围，再对材料标题做不区分大小写的包含过滤，最后删除空正文、截断每条 800 字、取前 4 条并从 1 编号。

选择理由：把白名单下推并在回表时再次检查，可以减少越界候选且抵抗伪造 Qdrant payload。备选先执行全班检索再在 Controller 过滤容易把未授权正文带入日志或中间 DTO，也浪费远程查询结果。

### Decision 6: 系统消息、历史和不可信资料分层组装

Prompt builder 只接受服务端对象，按固定顺序构造系统消息：角色提示词或默认角色、命中技能或直接回答说明、有无依据规则、通用输出约束、上传内容不可信边界。“解题引导”限制由服务端附加，不能仅依赖技能原文。

历史保持原有 user/assistant role；当前问题和编号资料放入最后一条 user 消息。材料标题、正文和技能原始说明均用明确分隔符包裹并标记为数据，不拼成额外 system 消息。客户端多余控制字段由严格 DTO 拒绝；模型与材料输出在 Vue 中使用文本节点或安全分段渲染，不使用 `v-html`。

有引用时允许正文出现有效 `[n]`；无引用时仍调用新流式网关，输出过滤器移除 `[n]` 型标记且保存过滤后的正文。旧 `/api/ask` 继续在无候选时短路，二者不共用无依据响应策略。

选择理由：清晰的信任层级便于测试和审计。备选把检索资料放入 system prompt 会提升上传文本的指令权重；让客户端上传完整消息数组会允许伪造角色和系统规则。

### Decision 7: 使用 `StreamingResponseBody` 和可流式解析的 ChatGateway

后端为现有 `ChatGateway` 增加流式方法，使用当前 OpenAI-compatible `/chat/completions` 配置并发送 `stream=true`。实现通过 HTTP 响应 InputStream 增量解析供应商 SSE，只向编排器暴露新增文本片段；忽略心跳，拒绝畸形 JSON、空 choices 和非预期结束，并对状态码、超时和错误内容使用现有脱敏规则。

Controller 在所有首帧前步骤以及上游连接成功后返回 `StreamingResponseBody`。异步任务不依赖请求线程中的 SecurityContext，而使用首帧前已经校验并复制的用户、会话和本轮快照。SSE 每帧采用 `event: <type>\ndata: <json>\n\n`，UTF-8 写出后立即 flush：

1. `meta`：状态、可空技能和引用；
2. `delta`：仅本次新增的过滤后文本；
3. `done`：助手消息事务提交成功后的消息 ID；
4. `error`：首帧后失败时的稳定代码和脱敏文案。

流开始后若已有正文失败，服务端以 `FAILED` 状态尽力保存部分正文、技能和引用，然后尽力发送 `error`，绝不发送 `done`。没有正文时不创建助手消息。若客户端已断开，发送事件可能失败，但服务端仍记录脱敏错误并完成相同持久化策略。正常正文保存失败也发送 `error` 而不是 `done`。

选择理由：`StreamingResponseBody` 与当前 Spring MVC、POST JSON 和顺序写帧契合，不需引入 WebFlux。备选 `SseEmitter` 也可流式，但其发送回调和异常生命周期更分散；原生 `EventSource` 不能携带本接口的 POST 请求体和 Authorization header。

### Decision 8: 用独立 Nginx 路径关闭缓冲并设置有界异步执行器

在通用 `/api/` 之前为 `/api/conversations/` 的消息流路径配置更具体的 location，保留认证头和转发头，并设置 `proxy_buffering off`、`proxy_cache off`、合理的 `proxy_read_timeout`。应用响应同时设置 `Cache-Control: no-cache` 与 `X-Accel-Buffering: no`。

Spring MVC 异步执行器使用有界线程池和队列；饱和时如果尚未发送首帧则返回脱敏 503，不无限创建线程。单轮上游读取使用现有可配置超时，并在终止、断开或异常后关闭流资源。

选择理由：只为流式路径关闭缓冲，避免无意改变上传和普通 JSON API。备选全局禁用代理缓冲会降低静态与普通 API 效率；无界线程会在模型变慢时耗尽进程资源。

### Decision 9: Vue 持久化会话页自己解析 SSE，并复用现有引用交互

新增教师配置路由和会话路由，继续使用 `AppShell`、现有颜色/间距令牌、反馈组件和材料选择数据。学生与教师共用会话页；教师额外看见配置导航。会话页采用左侧可折叠会话列表、主消息滚动区和底部紧凑输入器，窄屏时列表改为抽屉，不重做独立主题。

流式请求使用现有 token 获取函数构造 `fetch`。解析器用 `TextDecoder(..., {stream: true})` 和尾部缓冲按空行解帧，支持一块多帧、一帧多块、CRLF、UTF-8 跨块和最终残片。`meta` 初始化当前助手占位及引用，`delta` 只追加，`done` 用持久化 ID 标记完成；`error`、非法 JSON 或无 `done` 断线都保留部分正文并提供以同一问题重新提交的操作。提交期间禁用该会话输入，防止同一浏览器并发轮次。

刷新或切换会话一律从服务端详情恢复。回答编号用安全文本分段渲染并定位同轮引用卡；引用上下文继续跳转已有 `/materials?materialId=...&chunkId=...`。前端不重排引用、不缓存系统提示词，也不把 `sessionStorage` 令牌写入 URL 或日志。

选择理由：手写小型 SSE 解帧器是带 JSON POST 的必要适配，并可独立单测。备选把临时消息继续保存在浏览器会失去刷新恢复；引入新的聊天 UI 库会破坏现有视觉和增加依赖。

### Decision 10: Springdoc 生成文档，业务接口仍由安全链保护

增加与 Spring Boot 3.3.x 兼容的 `springdoc-openapi-starter-webmvc-ui`，使用 Controller/DTO 注解描述 Bearer security scheme、角色语义、普通错误响应及 `text/event-stream`。README 记录实际 `/swagger-ui/index.html` 与 `/v3/api-docs` 路径。只允许匿名读取这两个文档资源；所有 `/api/**` 业务接口仍执行现有 JWT 链和服务层授权。

SSE 文档提供四类事件的 schema 示例，但不把供应商 URL、模型密钥、数据库凭据、种子口令或真实令牌写入注解和示例。

选择理由：由实现声明生成文档比维护独立 YAML 更不易漂移。备选手写 OpenAPI 文件会产生第二份 DTO/路径事实源。

### Decision 11: 测试按纯逻辑、HTTP/持久化、网关和浏览器协议分层

- 纯单元测试覆盖技能解析、Unicode 限长、路由计分、历史窗口、prompt 信任边界、无依据编号清理和 SSE 解帧。
- Repository/服务集成测试使用 MySQL Testcontainers，验证 V4→V5 与空库迁移、同班/跨班、原子替换、会话归属、种子幂等及允许材料集合。
- 网关测试使用本地 mock HTTP server 模拟分块、UTF-8 拆分、上游错误和超时，不访问真实密钥。
- MockMvc/前端测试覆盖首帧前状态码、事件顺序、部分失败、刷新恢复、角色控件、引用跳转与长对话。
- Compose 人工验收确认 Nginx 未缓冲，并使用两个班级和教师/学生账户验证真实授权边界。

选择理由：只做 Controller mock 无法证明迁移、代理和网络分块；所有测试都调用真实模型又慢且会消耗密钥。分层后算法可快速重复，基础设施风险仍有针对性覆盖。

## Risks / Trade-offs

- [V5 重构 `skills.assistant_id` 可能丢失旧关联] → 迁移先复制并核对行数，再删除旧外键/列；增加 V4 快照升级和空库测试。
- [关联表无法用普通外键直接证明两端同班] → 写服务批量按当前班级验证，读取时同时限定三方 `class_id`，并用跨班造数集成测试防回归。
- [教师在流式生成中修改绑定] → 首帧前创建不可变本轮快照；修改只影响下一轮，保证单轮引用与提示一致。
- [用户消息已保存但准备阶段失败，页面看似缺少回答] → 这是规约要求的审计记录；详情显示该用户消息，前端提供重试，不创建空助手消息。
- [部分回答保存会让历史包含不完整内容] → 用 `FAILED` 状态清楚标记并排除模型历史窗口，UI 显示中断，不发送 `done`。
- [模型在无依据时持续生成引用标记] → 增量过滤器处理跨 delta 的引用模式，持久化和对外正文只使用过滤后文本；单元测试覆盖标记跨块。
- [SSE 线程被慢模型占用] → 有界执行器、连接/读取超时、代理超时和资源关闭共同限制占用；饱和在首帧前返回 503。
- [消息引用 JSON 随 DTO 演进难查询] → 引用是小型不可变展示快照，查询仍通过材料/切片表；JSON schema 由应用版本读取并做兼容默认。
- [Swagger 公开扩大信息面] → 仅公开结构且不含内部配置，所有业务数据和试调仍需 Bearer Token；生产如需关闭可用环境配置控制 UI，不改变 API。

## Migration Plan
