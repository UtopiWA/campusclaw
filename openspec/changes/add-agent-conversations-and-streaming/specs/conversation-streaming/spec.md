# Spec Delta

## Purpose

定义按用户和班级隔离的持久化智能体会话，以及每轮确定性技能路由、限定材料检索、可信消息组装、SSE 增量输出、历史恢复和可交互引用的完整行为契约。

## ADDED Requirements

### Requirement: 私有持久化会话
系统 MUST 允许已登录用户为本班已启用智能体创建持久化会话，并只允许会话所属用户在当前班级中列出、读取和继续该会话。

#### Scenario: 创建会话并锁定智能体
- **WHEN** 已登录用户选择本班已启用智能体创建会话
- **THEN** 系统 MUST 创建归属于当前用户和当前班级的会话，初始标题为“新的提问”
- **AND** 会话 MUST 永久记录该智能体标识，后续消息中的其他智能体或班级编号 MUST 被忽略或拒绝

#### Scenario: 选择无权使用的智能体
- **WHEN** 用户使用不存在、其他班级或已停用的智能体编号创建会话
- **THEN** 系统 MUST 返回与不存在编号一致的 HTTP 404
- **AND** 系统 MUST NOT 创建会话或泄露目标智能体状态

#### Scenario: 读取自己的本班会话
- **WHEN** 用户请求会话列表或自己的本班会话详情
- **THEN** 列表 MUST 按 `updatedAt` 倒序返回，详情 MUST 包含按写入顺序排列的消息
- **AND** 页面刷新后 MUST 能依据该响应恢复会话标题、智能体、正文、技能和引用

#### Scenario: 读取他人或其他班级会话
- **WHEN** 用户使用他人、其他班级或不存在的会话编号请求详情或继续提问
- **THEN** 系统 MUST 返回完全一致的 HTTP 404
- **AND** 响应 MUST NOT 泄露会话、智能体、问题、回答、技能或引用内容

#### Scenario: 智能体停用后的已有会话
- **WHEN** 会话创建后其智能体被教师停用
- **THEN** 该会话所属用户 MUST 仍能读取并继续会话
- **AND** 已停用智能体 MUST NOT 再用于创建新会话

### Requirement: 消息持久化与有限历史窗口
系统 MUST 按顺序持久化用户和助手消息，在生成前保存本轮问题，并只把最近 6 条有效历史消息送入本轮模型上下文，每条最多保留 500 个 Unicode 字符。

#### Scenario: 首轮问题更新会话标题
- **WHEN** 用户在标题仍为“新的提问”的会话中提交首轮有效问题
- **THEN** 系统 MUST 在生成前保存用户消息，并将标题更新为去除首尾空白后问题的前 24 个 Unicode 字符
- **AND** 后续问题 MUST 只刷新会话更新时间，不得再次改写标题

#### Scenario: 构造有限历史窗口
- **WHEN** 会话已经包含超过 6 条历史消息并提交新问题
- **THEN** 系统 MUST 只把按写入顺序最靠后的 6 条有效 `user` 或 `assistant` 消息送入模型
- **AND** 每条上下文正文 MUST 截断到 500 个 Unicode 字符，更早消息仍 MUST 保留并可在会话详情查看

#### Scenario: 问题内容不合法
- **WHEN** 用户提交去除首尾空白后少于 2 个或超过 500 个 Unicode 字符的问题
- **THEN** 系统 MUST 返回 HTTP 400
- **AND** 系统 MUST NOT 创建消息、修改标题、执行检索或调用对话网关

#### Scenario: 流开始前的后续处理失败
- **WHEN** 用户消息已经提交，但检索或对话准备在首个 SSE 事件前失败
- **THEN** 系统 MUST 保留该用户消息作为可审计的失败尝试，并返回对应 HTTP 503
- **AND** 系统 MUST NOT 创建空的正常助手消息

### Requirement: 确定性单技能路由
系统 MUST 只在会话智能体当前绑定、本班且已启用的技能中，按适用条件的词法子串命中数选择至多一个技能，且相同输入和配置 MUST 得到相同结果。

#### Scenario: 选择最高分技能
- **WHEN** 一项候选技能的适用条件在忽略大小写后命中问题中的关键词数多于其他候选
- **THEN** 系统 MUST 只选择该技能
- **AND** `meta` 事件及持久化助手消息 MUST 记录其名称

#### Scenario: 同分和零分
- **WHEN** 多项候选技能得到相同的最高正分
- **THEN** 系统 MUST 选择数据库标识最小的一项
- **AND** 当所有候选得分为 0 或候选集为空时，系统 MUST 不选择技能并按智能体角色直接回答

#### Scenario: 未绑定或停用技能命中关键词
- **WHEN** 问题命中未绑定、已停用或其他班级技能的适用条件
- **THEN** 该技能 MUST NOT 参与评分或出现在系统消息、SSE 事件及持久化消息中

#### Scenario: 解题引导技能被选中
- **WHEN** 被选技能名称包含“解题引导”
- **THEN** 服务端系统消息 MUST 要求只指出下一步检查方向，不输出最终答案、选项、得数或完整解题过程

### Requirement: 智能体限定材料检索与连续引用
系统 MUST 在当前班级内只检索会话智能体当前绑定的 READY 材料，使用既有混合检索取得至多 4 条可靠切片，并在全部过滤完成后从 1 连续建立本轮引用。

#### Scenario: 只命中绑定材料
- **WHEN** 本班绑定和未绑定材料都包含与问题相关的 READY 切片
- **THEN** 本轮检索和引用 MUST 只包含智能体绑定材料
- **AND** 未绑定材料即使相关度更高也 MUST NOT 出现在模型上下文、SSE 或消息历史中

#### Scenario: 技能限制资料范围
- **WHEN** 被选技能具有非空资料范围
- **THEN** 系统 MUST 在绑定材料候选中只保留标题包含该范围文本的材料
- **AND** 空正文和不匹配材料 MUST 在编号前移除

#### Scenario: 连续编号和正文长度
- **WHEN** 过滤后存在一条或多条可靠切片
- **THEN** 系统 MUST 按最终顺序从 `[1]` 连续编号，每条送入模型的正文最多 800 个 Unicode 字符
- **AND** 引用 MUST 包含编号、材料标识、标题、切片标识、切片序号和可直接展示的摘录，编号 MUST 与数组位置一致

#### Scenario: 没有绑定材料或没有可靠切片
- **WHEN** 智能体未绑定材料，或班级、绑定、状态、学科和相关度过滤后没有切片
- **THEN** 系统 MUST 使用空引用继续智能体流式回答
- **AND** 系统 MUST NOT 回退到本班全部材料、其他班级材料或低于既有阈值的候选

### Requirement: 可信消息组装与无依据回答
系统 MUST 由服务端构造本轮系统消息和资料消息，将智能体角色、至多一个技能及固定安全边界放入系统消息，将学生问题、历史和编号资料作为用户/助手上下文，并把上传内容视为数据而不是可执行指令。

#### Scenario: 有依据时组装消息
- **WHEN** 本轮检索返回可靠切片
- **THEN** 系统消息 MUST 要求优先依据编号资料并使用有效 `[n]`，用户消息 MUST 包含当前问题和对应编号资料
- **AND** 回答中的有效编号 MUST 指向本轮 `meta` 和持久化消息中的同序引用

#### Scenario: 无依据时仍按智能体回答
- **WHEN** 本轮引用为空
- **THEN** 系统 MUST 仍调用流式对话网关并按智能体角色及命中技能生成回答
- **AND** 对外正文 MUST 移除所有 `[n]` 形式编号，引用 MUST 为空，回答 MUST NOT 整段等于“资料中未找到相关内容”或编造出处

#### Scenario: 上传内容尝试改变系统行为
- **WHEN** 技能说明、材料标题或材料正文包含忽略规则、泄露信息、执行脚本或调用外部工具等指令
- **THEN** 系统 MUST 将这些内容放在不可信数据边界内，不得据此扩大权限或触发工具
- **AND** 前端 MUST 以不可执行文本展示模型正文和引用内容

#### Scenario: 客户端提交控制字段
- **WHEN** 客户端在提问中提交系统消息、角色、班级、用户、智能体覆盖值、技能或材料范围
- **THEN** 系统 MUST 忽略或拒绝这些控制字段，并只使用服务端读取的会话与配置

#### Scenario: 既有依据问答保持原语义
- **WHEN** 用户调用既有 `POST /api/ask` 且本班混合检索没有可靠切片
- **THEN** 系统 MUST 继续返回固定无依据文案和空引用，且 MUST NOT 调用对话网关
- **AND** 新流式会话的无依据生成行为 MUST NOT 改变该接口

### Requirement: SSE 增量回答协议
系统 MUST 对智能体提问返回 UTF-8 `text/event-stream`，按 `meta`、零到多条 `delta`、`done` 的正常顺序逐帧刷新，并在流开始后的失败中使用 `error` 事件而不是伪造新的 HTTP 状态。

#### Scenario: 正常流式回答
- **WHEN** 会话、路由和检索准备成功且对话网关持续返回文本
- **THEN** 第一帧 MUST 是 `meta`，包含状态、可空技能和本轮引用数组；后续每条 `delta` MUST 只包含新增文本
- **AND** 所有 `delta` 按序拼接 MUST 等于最终持久化正文，持久化成功后最后发送的 `done` MUST 包含助手消息标识

#### Scenario: 流开始前失败
- **WHEN** 认证、问题校验、会话归属、智能体读取、用户消息保存、绑定检索或对话连接在首帧前失败
- **THEN** 系统 MUST 返回对应的 JSON HTTP 400、401、403、404 或 503
- **AND** 响应 MUST NOT 声称为已开始的 SSE 流

#### Scenario: 流开始后失败且已有正文
- **WHEN** 至少一条 `delta` 已发送后对话网关、数据库或客户端连接发生失败
- **THEN** 服务端 MUST 尽力把已产生正文及本轮技能和引用持久化为明确的失败助手消息，而不是正常完成消息
- **AND** 连接仍可写时 MUST 发送脱敏 `error`；连接已断开时 MUST 记录脱敏失败结果，HTTP 状态保持 200 且流 MUST NOT 发送正常 `done`

#### Scenario: 流开始后失败且没有正文
- **WHEN** `meta` 已发送但尚无任何 `delta` 时发生失败
- **THEN** 系统 MUST 发送一条 `error` 事件并结束
- **AND** 系统 MUST NOT 创建空的正常助手消息或泄露供应商响应、密钥、内部地址和堆栈

#### Scenario: 代理和服务端不缓冲
- **WHEN** 对话网关产生多个时间上分离的文本片段
- **THEN** 浏览器 MUST 在生成完成前观察到多个独立 `delta` 事件
- **AND** 响应 MUST 使用 `Cache-Control: no-cache` 与 `X-Accel-Buffering: no`，反向代理 MUST 禁用该流式路径的缓冲和缓存

### Requirement: 可恢复的流式会话界面
系统 MUST 在现有应用壳中提供响应式会话页面，通过携带 Bearer Token 的 `fetch` POST 解码 SSE，逐段展示回答，并从服务端会话历史恢复消息、技能和引用。

#### Scenario: 创建和恢复会话
- **WHEN** 用户选择可用智能体开始会话，或刷新已有会话页面
- **THEN** 页面 MUST 显示本人的会话列表和当前会话消息，并保持会话绑定的智能体不可在当前会话内切换
- **AND** 刷新后内容 MUST 来自服务端持久化记录，而不是只依赖浏览器内存

#### Scenario: 增量解码网络数据
- **WHEN** SSE 帧跨多个网络数据块、一个数据块包含多帧或 UTF-8 字符跨块到达
- **THEN** 前端 MUST 使用流式文本解码和尾部缓冲完整还原事件
- **AND** 页面 MUST 只追加 `delta.text`，不得把累计正文重复渲染

#### Scenario: 展示技能与引用
- **WHEN** `meta` 包含技能和一条或多条引用
- **THEN** 页面 MUST 在对应助手轮次展示技能名和按编号连续排列的引用标题、位置及摘录
- **AND** 引用 MUST 提供现有 `materialId + chunkId` 材料上下文入口，MUST NOT 在前端重算编号

#### Scenario: 流异常或意外断开
- **WHEN** 页面收到 `error`、非法事件数据，或连接在 `done` 前结束
- **THEN** 页面 MUST 将错误关联到本轮问题并停止忙碌状态，保留已经显示的文本和引用
- **AND** 页面 MUST 提供可理解的重试方式，不得清空其他会话或消息

#### Scenario: 窄屏和键盘操作
- **WHEN** 用户在窄屏或只使用键盘访问会话页面
- **THEN** 会话列表、智能体选择、消息滚动区、输入器、引用和错误操作 MUST 保持可达且无横向遮挡
- **AND** 页面 MUST 复用现有 `AppShell`、按钮、反馈、模态框和设计令牌

### Requirement: 教师配置界面
系统 MUST 在现有应用壳中为教师提供智能体和技能配置界面，并为学生隐藏管理入口；服务端权限仍是最终授权边界。

#### Scenario: 教师维护配置
- **WHEN** 教师进入配置页面
- **THEN** 页面 MUST 支持创建和修改智能体、启停状态、技能/材料绑定，以及创建、编辑和删除技能文本
- **AND** 页面 MUST 展示字段校验、跨班隐藏语义和保存失败，失败时保留尚未提交的编辑内容

#### Scenario: 学生访问配置页面或写接口
- **WHEN** 学生直接访问配置路由或调用写接口
- **THEN** 前端 MUST 不展示管理控件，服务端 MUST 返回 HTTP 403
- **AND** 任何配置和绑定 MUST 保持不变

### Requirement: OpenAPI 与 Swagger 文档
系统 MUST 从后端接口声明生成 OpenAPI，并提供可访问的 Swagger UI，使文档中的路径、Bearer 认证、角色限制、请求响应模型和 SSE 媒体类型与实际行为一致。

#### Scenario: 查看和试调接口文档
- **WHEN** 开发者打开 README 记录的 Swagger UI 地址
- **THEN** 页面 MUST 列出智能体、技能、会话和流式消息接口，并提供 Bearer 认证方案
- **AND** 使用有效教师或学生令牌试调非流式接口时，结果 MUST 与应用页面调用一致

#### Scenario: 文档不泄露秘密
- **WHEN** 匿名用户读取 OpenAPI 描述或 Swagger 静态页面
- **THEN** 文档 MAY 展示公开的接口结构，但 MUST NOT 包含真实令牌、模型密钥、数据库凭据、内部服务地址或演示口令
- **AND** 受保护业务接口 MUST 继续要求有效 Bearer Token
