# Spec Delta

## Purpose

定义教师按班级维护智能体、技能文本及其材料绑定的可观察行为，使学生只能选用本班已启用配置，并保证所有绑定、校验和迁移结果可安全用于后续会话编排。

## ADDED Requirements

### Requirement: 本班智能体配置
系统 MUST 允许教师创建和修改本班智能体的名称、角色提示词、启用状态、技能绑定及材料绑定，并将一次提交中的智能体字段和两类绑定作为一个原子配置更新。

#### Scenario: 教师创建带绑定的智能体
- **WHEN** 教师提交不超过 64 个 Unicode 字符且在本班唯一的名称、不超过 2000 个字符的提示词、启用状态以及本班技能和材料编号
- **THEN** 系统 MUST 创建本班智能体并保存去重后的两类绑定
- **AND** 响应 MUST 返回智能体标识、名称、提示词、启用状态和当前绑定标识

#### Scenario: 空提示词使用默认角色
- **WHEN** 教师创建或修改智能体并将提示词留空或只提交空白
- **THEN** 系统 MUST 保存空提示词而不是拒绝请求
- **AND** 后续回答 MUST 使用服务端定义的默认角色设定

#### Scenario: 配置字段不合法
- **WHEN** 教师提交空名称、超长名称、超长提示词或与本班现有智能体重名的名称
- **THEN** 系统 MUST 返回 HTTP 400 和可理解的字段错误
- **AND** 智能体字段及既有绑定 MUST 保持不变

#### Scenario: 绑定不存在或其他班级资源
- **WHEN** 教师提交不存在或不属于本班的技能或材料编号
- **THEN** 系统 MUST 返回 HTTP 404，且 MUST NOT 泄露目标资源是否存在或属于哪个班级
- **AND** 智能体字段和两类绑定 MUST 全部保持原状，不得只保存部分配置

### Requirement: 智能体可见性与写权限
系统 MUST 使用 Bearer JWT 对应用户在数据库中的最新角色和 `class_id` 决定智能体可见范围与写权限，MUST NOT 采信客户端提交的角色、班级或配置归属。

#### Scenario: 教师列出本班全部智能体
- **WHEN** 已登录教师请求智能体列表
- **THEN** 系统 MUST 返回本班已启用和已停用智能体及其管理所需配置
- **AND** 响应 MUST NOT 包含其他班级智能体

#### Scenario: 学生只发现可选智能体
- **WHEN** 已登录学生请求智能体列表或按编号读取智能体
- **THEN** 系统 MUST 只返回本班已启用智能体的学生可用摘要
- **AND** 摘要 MUST NOT 暴露角色提示词、内部绑定实现或其他班级配置

#### Scenario: 学生调用智能体写接口
- **WHEN** 学生尝试创建、修改、启停或变更智能体绑定
- **THEN** 系统 MUST 返回 HTTP 403
- **AND** 所有智能体、技能和材料绑定 MUST 保持不变

#### Scenario: 按编号访问不可见智能体
- **WHEN** 用户按编号访问不存在、其他班级或对该用户不可见的智能体
- **THEN** 系统 MUST 返回与真实不存在资源一致的 HTTP 404
- **AND** 响应 MUST NOT 通过状态码或正文泄露目标资源存在性

### Requirement: 项目技能文本管理
系统 MUST 允许教师用单一 UTF-8 文本创建和修改本班技能，按第一个空行分隔元数据与说明正文，保存结构化字段及原始文本，并只允许声明 `knowledge_search` 工具。

#### Scenario: 解析合法技能文本
- **WHEN** 教师提交总长度不超过 8000 个 Unicode 字符，且包含合法的名称、适用条件、资料、工具、启用字段和非空说明正文
- **THEN** 系统 MUST 解析并保存名称、触发文本、资料范围、工具列表、启用状态、说明及完整原文
- **AND** 名称 MUST 不超过 32 个字符，适用条件 MUST 不超过 120 个字符，资料范围 MUST 不超过 32 个字符，说明 MUST 不超过 2000 个字符

#### Scenario: 忽略元数据注释
- **WHEN** 技能元数据区包含以 `#` 开头的注释行或字段之间的空白
- **THEN** 系统 MUST 忽略注释并规范化字段两侧空白
- **AND** 第一个分隔元数据与正文的空行之后的内容 MUST 作为说明正文保留

#### Scenario: 技能文本不合法
- **WHEN** 技能文本缺少名称、适用条件、启用或说明，包含重复字段、未知字段、非法启用值、非 `knowledge_search` 工具，或任何长度超过限制
- **THEN** 系统 MUST 返回 HTTP 400 和面向教师的可读错误
- **AND** 系统 MUST NOT 创建新技能或覆盖已有技能及其绑定

#### Scenario: 班内技能名称重复
- **WHEN** 教师创建技能或修改技能名称后与本班另一技能重名
- **THEN** 系统 MUST 返回 HTTP 400
- **AND** 其他班级使用相同技能名称 MUST NOT 构成冲突

#### Scenario: 教师删除技能
- **WHEN** 教师删除本班技能
- **THEN** 系统 MUST 删除该技能及其全部智能体绑定
- **AND** 其他技能、智能体、材料、会话和历史消息 MUST 保持不变

### Requirement: 安全删除智能体
系统 MUST 允许教师删除本班尚未产生历史消息的智能体，并在智能体已有真实消息历史时拒绝硬删除，以避免消息被静默级联或失去归属。

#### Scenario: 删除只有空会话的智能体
- **WHEN** 教师删除本班智能体，且该智能体没有会话或只有零消息的“新的提问”空会话
- **THEN** 系统 MUST 先删除这些空会话，再返回成功并删除该智能体及其技能、材料绑定
- **AND** 技能、材料以及其他智能体 MUST 保持不变

#### Scenario: 拒绝删除已有历史消息的智能体
- **WHEN** 教师删除至少有一条会话包含消息的本班智能体
- **THEN** 系统 MUST 返回 HTTP 409 和可理解的停用建议
- **AND** 智能体、绑定、非空会话及历史消息 MUST 全部保持不变

### Requirement: 智能体列表快捷启停
教师配置页 MUST 在每个智能体卡片上提供与编辑、删除并列的启停开关，并继续通过完整智能体配置更新执行服务端校验。

#### Scenario: 从智能体列表切换启停状态
- **WHEN** 教师操作智能体卡片上的启停开关
- **THEN** 页面 MUST 提交名称、提示词、技能绑定、材料绑定和新启用状态的完整配置
- **AND** 成功后状态标签与开关 MUST 同步更新；失败时 MUST 恢复原状态并展示错误

#### Scenario: 越权删除智能体
- **WHEN** 学生删除智能体，或教师使用其他班级的智能体编号删除
- **THEN** 系统 MUST 分别返回 HTTP 403 或 404
- **AND** 目标智能体和绑定 MUST 保持不变

### Requirement: 技能可见性与写权限
系统 MUST 允许已登录用户列出本班技能，并只允许教师创建、修改或删除技能；所有按编号操作 MUST 同时限定当前班级。

#### Scenario: 同班用户列出技能
- **WHEN** 已登录教师或学生请求技能列表
- **THEN** 系统 MUST 只返回当前数据库 `class_id` 对应的技能
- **AND** 列表 MUST 明确提供名称、适用条件、资料范围、工具和启用状态

#### Scenario: 学生调用技能写接口
- **WHEN** 学生尝试创建、修改或删除技能
- **THEN** 系统 MUST 返回 HTTP 403
- **AND** 技能和全部绑定 MUST 保持不变

#### Scenario: 教师操作跨班技能
- **WHEN** 教师使用其他班级技能编号请求修改或删除
- **THEN** 系统 MUST 返回与不存在编号一致的 HTTP 404
- **AND** 目标技能及其绑定 MUST 保持不变

### Requirement: 结构化技能配置界面
教师配置页面 MUST 用结构化控件编辑技能名称、适用条件、资料范围、行为说明、启用状态和工具绑定，并继续把结果提交为服务端定义的单一技能文本；列表 MUST 提供无需进入编辑弹窗的启停开关。

#### Scenario: 通过表单创建或编辑技能
- **WHEN** 教师新建技能、编辑已有技能，或导入合法 UTF-8 技能文本
- **THEN** 页面 MUST 分别显示技能名称、触发条件、可选资料范围、行为说明和工具复选项，并在保存前保留教师可检查的字段值
- **AND** 页面 MUST 生成与服务端解析器兼容的中文技能文本，服务端仍 MUST 执行全部字段、工具和唯一性校验

#### Scenario: 在技能列表切换启用状态
- **WHEN** 教师操作某项技能的启停开关
- **THEN** 页面 MUST 使用该技能的完整当前配置提交更新，并在成功后展示服务端返回的最新状态
- **AND** 更新失败时 MUST 恢复原开关状态、显示可理解错误，且 MUST NOT 丢失或改写其他技能字段

### Requirement: 绑定配置即时生效
系统 MUST 在每轮回答开始时读取会话智能体当前的技能与材料绑定，而不是使用会话创建时的绑定快照；绑定查询 MUST 同时限定智能体、资源和当前班级。

#### Scenario: 已有会话使用更新后的绑定
- **WHEN** 教师在会话创建后停用或解绑技能，或修改智能体的材料绑定
- **THEN** 该会话下一轮回答 MUST 立即使用修改后的绑定
- **AND** 已持久化的历史消息、旧引用和会话选定的智能体 MUST NOT 被改写

#### Scenario: 空材料绑定是合法配置
- **WHEN** 智能体没有绑定任何材料
- **THEN** 系统 MUST 允许保存配置和继续对话
- **AND** 该智能体的流式回答 MUST 将本轮检索视为无依据，不得扩大到本班全部材料

### Requirement: 既有演示配置兼容升级
系统 MUST 在数据库升级后保留现有 `assistants` 和 `skills` 数据的班级归属、名称及原有关联，MUST NOT 因模型扩展而重复创建或静默丢弃已有演示配置。

#### Scenario: 既有数据库执行新迁移
- **WHEN** 包含 V1 至 V4 数据的数据库应用本次迁移
- **THEN** 每个既有智能体 MUST 仍以原标识、名称和班级存在
- **AND** 每个既有技能 MUST 转换为可读取的班级技能并保留与原智能体的绑定

#### Scenario: 空库从头执行全部迁移
- **WHEN** 系统在空数据库上从 V1 顺序执行到本次迁移并运行演示种子
- **THEN** 系统 MUST 创建一套满足新模型约束且可重复启动的演示智能体和技能
- **AND** 重复启动 MUST NOT 产生重复智能体、技能或绑定
