## ADDED Requirements

### Requirement: 问答专用材料采信
系统 MUST 对 `POST /api/ask` 与智能体绑定材料检索应用相同的问答采信门，在混合检索排序后先过滤弱候选，再选择至多 4 条可靠切片；直接搜索 MUST 保留原有宽召回，安全 MCP 工具结果仍按独立规则决定是否支持会话生成。

#### Scenario: 强向量候选单路通过
- **WHEN** 混合检索候选的向量余弦分数至少为默认 `0.55` 或配置的强向量阈值
- **THEN** 系统 MUST 允许该候选进入问答上下文，无论关键词路是否命中

#### Scenario: 双路候选以较低向量门槛通过
- **WHEN** 同一候选同时出现在 keyword 与 vector 结果中，且向量分数至少为默认 `0.45` 或配置的交叉确认阈值
- **THEN** 系统 MUST 允许该候选进入问答上下文，并继续使用 RRF 决定候选间顺序

#### Scenario: 弱候选不得触发模型
- **WHEN** 候选只有关键词命中，或其向量分数低于适用的问答采信门
- **THEN** 系统 MUST 从问答候选中删除该片段
- **AND** 全部候选被删除时 `POST /api/ask` MUST 返回“资料中未找到相关内容”、保持引用为空且不得调用 Chat；智能体会话仅在同轮仍有安全可用工具结果时 MAY 继续生成

#### Scenario: 先过滤再截取问答候选
- **WHEN** RRF 排名前列包含未通过采信门的候选，但各路已召回集合中仍有合格候选
- **THEN** 系统 MUST 先移除不合格候选，再按既有 RRF 顺序截取至多 4 条
- **AND** 系统 MUST NOT 将 RRF 融合分直接视为跨查询置信度

#### Scenario: 采信阈值配置顺序不合法
- **WHEN** 服务端配置未满足 `0 <= 宽召回阈值 <= 双路确认阈值 <= 强向量阈值 <= 1`
- **THEN** 系统 MUST 拒绝使用该配置启动，不得静默交换或放宽阈值

#### Scenario: 直接检索保持宽召回
- **WHEN** 用户调用公开检索接口选择 keyword、vector 或 hybrid 模式
- **THEN** 系统 MUST 继续返回经过既有召回门、班级和 READY 校验的排序结果
- **AND** 问答专用采信门 MUST NOT 隐式删除供用户浏览的搜索结果
