# agent-configuration Specification Delta

## MODIFIED Requirements

### Requirement: 项目技能文本管理
系统 MUST 允许教师用单一 UTF-8 文本创建和修改本班技能，按第一个空行分隔元数据与说明正文，保存结构化字段及原始文本，并允许工具字段声明内置 `knowledge_search` 或一个及以上 `工具名@服务名` 引用。

#### Scenario: 解析合法技能文本
- **WHEN** 教师提交总长度不超过 8000 个 Unicode 字符，且包含合法的名称、适用条件、资料、工具、启用字段和非空说明正文
- **THEN** 系统 MUST 解析并保存名称、触发文本、资料范围、有序工具列表、启用状态、说明及完整原文
- **AND** 名称 MUST 不超过 32 个字符，适用条件 MUST 不超过 120 个字符，资料范围 MUST 不超过 32 个字符，说明 MUST 不超过 2000 个字符

#### Scenario: 规范化多个工具引用
- **WHEN** 工具字段使用中英文逗号、顿号、分号、竖线或换行分隔多个合法引用，且同一引用出现多次
- **THEN** 系统 MUST 按首次出现顺序去重并保存规范化引用
- **AND** `knowledge_search` MUST 作为内置标记保留但 MUST NOT 被解析为 MCP 网络工具

#### Scenario: 忽略元数据注释
- **WHEN** 技能元数据区包含以 `#` 开头的注释行或字段之间的空白
- **THEN** 系统 MUST 忽略注释并规范化字段两侧空白
- **AND** 第一个分隔元数据与正文的空行之后的内容 MUST 作为说明正文保留

#### Scenario: 技能引用可用的本班 MCP 工具
- **WHEN** 教师保存包含 `工具名@服务名` 的技能，且每个引用都对应当前班级已连接服务的已发现工具
- **THEN** 系统 MUST 在一个事务中保存规范化工具列表和完整技能
- **AND** 系统 MUST NOT 把服务 Token、地址或工具原始 Schema 写入技能文本

#### Scenario: 技能文本不合法
- **WHEN** 技能文本缺少名称、适用条件、启用或说明，包含重复字段、未知字段、非法启用值、非法工具引用，或任何长度超过限制
- **THEN** 系统 MUST 返回 HTTP 400 和面向教师的可读错误
- **AND** 系统 MUST NOT 创建新技能或覆盖已有技能及其绑定

#### Scenario: 技能引用不可用工具
- **WHEN** 工具引用对应不存在、其他班级、未连接或未发现的服务或工具
- **THEN** 系统 MUST 返回 HTTP 400 和统一的“工具不可用”错误，不得泄露资源存在性或所属班级
- **AND** 技能字段、原文和智能体绑定 MUST 全部保持原状

#### Scenario: 班内技能名称重复
- **WHEN** 教师创建技能或修改技能名称后与本班另一技能重名
- **THEN** 系统 MUST 返回 HTTP 400
- **AND** 其他班级使用相同技能名称 MUST NOT 构成冲突

#### Scenario: 教师删除技能
- **WHEN** 教师删除本班技能
- **THEN** 系统 MUST 删除该技能及其全部智能体绑定
- **AND** 其他技能、智能体、材料、MCP 服务、会话和历史消息 MUST 保持不变

### Requirement: 结构化技能配置界面
教师配置页面 MUST 用结构化控件编辑技能名称、适用条件、资料范围、行为说明、启用状态和多工具绑定，并继续把结果提交为服务端定义的单一技能文本；列表 MUST 提供无需进入编辑弹窗的启停开关。

#### Scenario: 通过表单创建或编辑技能
- **WHEN** 教师新建技能、编辑已有技能，或导入合法 UTF-8 技能文本
- **THEN** 页面 MUST 分别显示技能名称、触发条件、可选资料范围、行为说明、内置工具和已连接本班 MCP 工具的复选项，并在保存前保留教师可检查的字段值与顺序
- **AND** 页面 MUST 生成与服务端解析器兼容的中文技能文本，服务端仍 MUST 执行全部字段、工具可用性和唯一性校验

#### Scenario: 导入包含多个工具的技能文本
- **WHEN** 教师导入包含多个合法工具引用的 UTF-8 技能文本
- **THEN** 页面 MUST 将规范化后的引用恢复为相应复选状态，并保留无法匹配当前工具缓存的引用供教师修正
- **AND** 页面 MUST NOT 静默丢弃、替换或重新排序教师提交的工具引用

#### Scenario: 在技能列表切换启用状态
- **WHEN** 教师操作某项技能的启停开关
- **THEN** 页面 MUST 使用该技能的完整当前配置和全部工具引用提交更新，并在成功后展示服务端返回的最新状态
- **AND** 更新失败时 MUST 恢复原开关状态、显示可理解错误，且 MUST NOT 丢失或改写其他技能字段

## ADDED Requirements

### Requirement: 技能工具存储兼容升级
系统 MUST 将既有单工具字段迁移为非空的多工具引用字段，并保留迁移前的技能文本、班级归属、名称、启用状态和智能体绑定。

#### Scenario: 迁移现有 knowledge_search 技能
- **WHEN** 包含 Class05 `skills.tool_name` 数据的数据库执行 V6 迁移
- **THEN** 每条原有 `knowledge_search` MUST 成为新字段中的唯一规范化引用
- **AND** 技能原文、结构化字段和智能体绑定 MUST 保持可读且语义不变

#### Scenario: 空库执行全部迁移
- **WHEN** 空数据库从 V1 顺序执行到 V6 并运行演示种子
- **THEN** 所有技能 MUST 使用新的非空多工具字段且可被解析
- **AND** 重复启动 MUST NOT 产生重复技能、MCP 服务或绑定
