# Proposal

## Why

CampusClaw 需要先建立可信的身份与班级数据边界，才能安全地承载校本教学材料。当前项目尚无业务实现，本变更先形成登录、角色授权、班级隔离和材料入库的最小可运行基础，为后续检索与智能助手能力提供可靠数据源。

## What Changes

- 新增教师和学生两类账号的密码登录、服务端会话和登出能力；未登录用户不能读取受保护业务数据。
- 新增服务端角色授权：教师可以上传和管理本班材料，学生只能读取本班材料，学生写请求返回 HTTP 403。
- 将班级定义为强制数据边界：列表、按 ID 访问和写入均从会话获取 `class_id`，禁止客户端覆盖归属班级。
- 新增教学材料完整文件流程：首版接收 `.txt`、`.md`，完成安全落盘、文本解析以及材料与知识条目的事务写入；同班教师和学生可在线查看纯文本内容并下载原文件。
- 新增与教师示例 Demo 一致的可复用应用框架：固定侧边栏、班级顶栏、浅灰工作区、红色设计令牌、卡片/按钮/弹窗等共享视觉规范，后续业务页面复用同一套页面骨架。
- 新增双班级种子数据和核心领域结构，用于验证登录、角色权限和跨班隔离。
- 新增密码哈希、环境变量密钥、上传失败回滚等安全要求。
- 规划 Docker Compose 标准启动方式、数据与上传目录持久化，以及无需登录的 `GET /health` 健康检查。
- 补充从零启动、预置账号和验收方法的 README 说明；实际实现留到 Apply 阶段。

## Capabilities

### New Capabilities

- `auth-upload`: 覆盖登录与会话、教师/学生角色授权、班级隔离、教学材料上传/查看/下载和知识库入库、可验收种子数据、安全存储及 Compose 健康检查。

### Modified Capabilities

（无。项目当前没有已归档的主规格。）

## Impact

- 实现包含 Vue 前端、Spring Boot 后端、登录与材料 REST API/页面、MySQL 数据库、种子初始化、上传目录和知识库记录；材料元数据增加是否存在原文件及文件大小，但不得暴露服务器存储路径。
- 后续运行依赖预计包括 Node.js/npm、Vue 3、Vite、Java 17、Maven、Spring Boot 3、Spring Security、Spring Data JPA、MySQL 8 和 Docker Compose。
- 项目根后续将新增 `frontend/`、`backend/`、前后端容器构建文件、`docker-compose.yml` 和 `.env.example`；真实凭据、密钥与生成的数据文件不得提交。
- 本变更会成为后续检索、问答、作业和学科助手能力的身份及数据基础。

## Non-goals

- 不做 RAG、全文检索、智能问答、聊天助手、Agent 编排或技能运行时。
- 不做作业提交、自动批改、成绩、错题本、审计统计和学情画像。
- 不做开放注册、找回密码、短信或邮箱验证码、OAuth/OIDC、SSO。
- 不做多校、多租户或跨组织管理；本变更只验证两个班级的数据隔离。
- 不做 PDF、Office、图片或音视频解析；首版只支持 `.txt` 和 `.md`。
- 不做 Markdown 富文本渲染、文件在线编辑、版本管理、批量下载或公开分享链接；在线查看只展示不可执行的 UTF-8 纯文本。
- 不做 Kubernetes、多副本高可用、完整 CI/CD 或生产级运维；标准启动仅要求本地/演示环境的 Docker Compose。
- 不以隐藏按钮、禁用表单或客户端路由守卫替代服务端授权和班级过滤。
