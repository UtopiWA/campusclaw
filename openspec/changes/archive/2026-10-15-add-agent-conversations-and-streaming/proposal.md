# Proposal

## Why

CampusClaw 已能对本班材料进行可追溯检索和单次依据问答，但还没有可由教师配置的智能体、服务端持久化会话或真正的流式回答，页面刷新后也无法恢复连续学习过程。第 5 课需要把角色提示词、确定性技能路由、限定材料检索和 SSE 输出组合为一条可审计的回答链路，同时保留既有 `/api/ask` 的严格有依据语义。

## What Changes

- 允许教师管理本班智能体，并为每个智能体配置角色提示词、启用状态、技能绑定和材料绑定；启停开关直接与编辑、删除并列显示。删除时自动清理未产生消息的空会话，真正存在历史消息时拒绝删除并提示停用；学生只能发现和选用本班已启用智能体。
- 将现有简化的 `assistants`、`skills` 数据演进为可独立复用的智能体与班级技能模型，增加技能/材料绑定、会话和消息持久化，并无损迁移演示数据。
- 定义并解析项目自有的中文技能文本格式，执行字段、长度、唯一性和 `knowledge_search` 工具白名单校验。
- 新建会话时锁定一个智能体；每轮重新读取其当前绑定，使用确定性词法计分选择至多一个技能，并为“解题引导”等宽泛题型条件提供可解释的题目意图匹配，只在绑定材料内执行本班混合检索。
- 增加独立的智能体流式回答接口，以 `meta`、`delta`、`done`、`error` 四类 SSE 事件返回技能、引用和增量正文，并把用户消息、助手正文、引用及技能持久化。
- 增加教师配置页面和教师、学生共用的可恢复会话页面；技能配置以名称、触发条件、行为说明和工具绑定等结构化控件呈现，并提供列表启停开关和智能体删除入口。每个用户可删除自己的会话及其消息。会话主区占满可用空间，只保留历史列表与消息区各自必要的滚动，输入器固定在主区底部。
- 重新划分前端职责：教师和学生均在“讲义与检索”页面直接检索本班讲义，在“助手对话”中使用由教师配置知识库范围和技能的智能体进行持久化流式问答；旧 `/search` 跳转到讲义页面，避免两套问答入口并存。
- 通过 Spring Controller 注解生成 OpenAPI，并提供与实际路由、权限、DTO 和 SSE 媒体类型一致的 Swagger UI。
- 在仓库内增加按 URL 和 HTTP 方法组织的 Python 接口回归套件，以独立脚本覆盖登录、检索、提示词/技能和会话流式消息，并由统一入口生成不入库的 HTML 报告。
- 保持现有 Bearer JWT、班级隔离、材料处理、检索接口和 `/api/ask` 行为不变；新流式链路无依据时同样不调用模型并返回固定文案。流完成时按正文首次引用顺序过滤并从 1 重写引用及正文编号；对话请求可用配置关闭不会展示的模型推理阶段，前端以独立渲染队列逐字消费供应商批量送达或单条过大的增量，保持可辨识的流式输出。
- 收紧智能体 RAG：没有可靠切片时不调用模型并返回固定无依据答复；有可靠切片时强制引用，模型漏标时按回答与候选正文的文本重合度选择一条依据并补为 `[1]`。引用卡片只在正文逐字展示完成后出现。
- 修正 Markdown `hierarchy` 切分：跨已解析知识条目维护 `#`～`###` 标题层级，纯标题不再独占切片，而是作为后续正文的检索上下文；重建索引后继续使用标准 RRF，并通过去除低信息标题片段改善混合检索。

## Capabilities

### New Capabilities

- `agent-configuration`: 本班智能体、技能文本、技能/材料绑定、教师写权限、学生可见性及配置即时生效规则。
- `conversation-streaming`: 私有持久化会话、消息窗口、技能路由、绑定材料检索、可信消息组装、SSE 协议、流式页面和 OpenAPI 文档。
- `api-regression-harness`: 仓库内 Python 接口脚本的目录约定、一键执行、响应与数据库联合断言、最小接口覆盖和脱敏 HTML 报告。

### Modified Capabilities

- `knowledge-retrieval`：细化 `hierarchy` 的连续标题和纯标题处理；不改变公开检索请求/响应字段或标准 RRF 公式。

## Impact

- 数据库：新增 migration，扩展或重构 `assistants`、`skills`，增加智能体—技能、智能体—材料、会话和消息关系；必须兼容当前 V1～V4 数据。
- 后端：新增智能体/技能/会话 API、技能解析与路由、限定材料检索编排、流式对话网关、SSE 响应和 OpenAPI 注解；现有认证用户和 `class_id` 仍是唯一权限来源。
- 前端：增加教师配置入口、会话列表、智能体选择、流式解帧与恢复；复用 `AppShell`、设计令牌和现有引用交互。
- 部署：Nginx 对流式接口关闭缓冲并放宽读取超时，同时从前端统一入口代理 Swagger UI 与 OpenAPI 描述；可能增加 Springdoc 代码依赖，但不增加新的运行时基础设施或客户端秘密。
- 文档与测试：更新 README 和 `learning`，补充数据库迁移、服务端权限、路由、提示组装、SSE、浏览器解帧、响应式页面和端到端验证；新增 `apitest/` Python 接口回归套件，生成的 HTML 报告不得提交到 Git。

## Non-goals

- 不改回 Cookie/Session，不改变 Bearer JWT 的签发、存储或现有权限边界。
- 不删除或改变 `/api/ask` 的“无依据不调用模型”行为，不改变公开检索 DTO、标准 RRF 公式或引用上下文授权。
- 不做 WebSocket、多人协作、语音、无限上下文、长期记忆总结或刷新令牌。
- 不做语义技能路由、多技能融合、模型自主选择技能、任意工具执行、MCP 调用或流式工具调用。
- 不把材料、技能文件或模型输出作为可信 HTML，也不允许客户端提交系统消息、角色、班级或检索范围。
- 不把前端隐藏控件当作授权，不新增跨班共享智能体、技能、会话或材料的能力。
