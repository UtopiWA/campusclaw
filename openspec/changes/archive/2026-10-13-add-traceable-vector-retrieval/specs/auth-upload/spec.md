# Spec Delta

## MODIFIED Requirements

### Requirement: 教学材料上传与知识库入库
教师上传受支持的教学材料后，系统 MUST 先安全保存原文件和材料记录，再通过后台任务异步解析文本、写入同班知识条目并建立检索索引。上传成功仅表示原文件与材料元数据已提交；本班材料列表 MUST 展示新记录及其待处理、解析中、索引中、可检索或失败状态，并为失败状态提供稳定且脱敏的处理阶段、失败代码和是否可重试信息。

#### Scenario: 教师上传有效文本材料
- **WHEN** 教师上传非空且未超过配置上限的 `.txt` 或 `.md` 文件
- **THEN** 系统 MUST 安全保存文件并创建一条 `PENDING` 材料记录
- **AND** 新材料的上传者与 `class_id` MUST 来自令牌用户在数据库中的当前记录
- **AND** 系统 MUST 返回 HTTP 201、新材料标识和 `PENDING` 状态，MUST NOT 等待正文解析、嵌入或向量写入完成
- **AND** 请求线程 MUST 只完成文件保存与材料提交，MUST NOT 为解析目的加载或处理完整正文

#### Scenario: 后台解析成功
- **WHEN** 已提交材料的后台任务成功按 UTF-8 解析正文
- **THEN** 系统 MUST 创建至少一条与该材料及班级关联的知识条目并继续建立索引
- **AND** 索引成功后材料 MUST 变为 `READY`，同一材料任务重复执行 MUST NOT 创建重复知识条目

#### Scenario: 同一材料被重复调度
- **WHEN** 上传回调、恢复扫描或教师重试在相近时间尝试处理同一材料
- **THEN** 系统 MUST 通过数据库条件更新原子认领该材料，每个处理版本只能有一个任务进入解析
- **AND** 未认领成功的任务 MUST 安全结束，MUST NOT 重复创建知识条目、切片或向量

#### Scenario: 上传后本班列表可见
- **WHEN** 教师收到成功上传响应后，本班教师或学生重新请求材料列表
- **THEN** 列表 MUST 立即显示该材料的标题、可用元数据和当前处理状态
- **AND** 另一班级用户的材料列表 MUST NOT 显示该材料

#### Scenario: 请求内可判定的无效文件被拒绝
- **WHEN** 教师上传非 `.txt`/`.md` 文件、空文件或超过配置上限的文件
- **THEN** 系统 MUST 返回明确的 HTTP 4xx 错误
- **AND** 材料表、知识条目表和上传目录 MUST NOT 留下该请求产生的记录或文件

#### Scenario: 后台解析失败
- **WHEN** 已提交文件无法按 UTF-8 解码、无法生成有效知识条目或后台知识条目事务失败
- **THEN** 系统 MUST 将材料标记为 `FAILED`，MUST NOT 生成可检索切片或半成品向量
- **AND** 系统 MUST 保留已安全提交的原文件，并以稳定失败代码区分永久输入错误与可重试处理错误，MUST NOT 向前端返回堆栈、供应商原文或内部地址
- **AND** 列表 MUST 明确显示失败阶段；可重试失败允许教师重新处理或删除，永久输入错误提示教师删除后重新上传有效文件

#### Scenario: 教师重新处理失败材料
- **WHEN** 教师对本班且标记为可重试的 `FAILED` 材料发起重新处理
- **THEN** 系统 MUST 将材料重新置为 `PENDING/QUEUED` 并交给同一有界后台流程
- **AND** 该操作 MUST 与只使用已有知识条目的“重建索引”保持不同接口和语义
- **AND** 学生调用重新处理接口 MUST 返回 HTTP 403，跨班材料 MUST 返回 HTTP 404

#### Scenario: 文件或材料主事务失败
- **WHEN** 原文件保存或材料记录写入在上传请求内失败
- **THEN** 系统 MUST 回滚该次上传产生的数据库变更并删除临时文件和未关联的最终文件
- **AND** 本班材料列表 MUST NOT 出现不完整记录

#### Scenario: 异步任务在进程退出前未完成
- **WHEN** 应用在 PENDING 或 INDEXING 材料处理完成前退出并再次启动
- **THEN** 应用就绪后的恢复调度 MUST 按小批量重新提交 `PENDING` 和超过超时阈值的 `INDEXING` 材料，MUST NOT 在启动线程同步解析全部积压材料
- **AND** 内存任务队列 MUST NOT 成为判断材料是否需要处理的唯一依据
- **AND** `FAILED` 材料 MUST NOT 在每次启动时被无条件重新处理

#### Scenario: 后台执行器暂时无法接收任务
- **WHEN** 有界执行器队列已满而拒绝刚提交的材料任务
- **THEN** 上传响应仍 MUST 表示原文件已经保存，材料 MUST 保持 `PENDING/QUEUED` 而不是被伪报为成功索引
- **AND** 后续恢复扫描 MUST 能再次提交该材料，页面轮询 MUST 有退避、最长等待和手动刷新出口
