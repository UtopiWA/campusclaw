# Design: Markdown 感知的知识条目与标题扫描

## Context

材料入库有两级边界：`TextParser` 先把原文件变成 `KnowledgeEntry`，`ChunkingService` 再把 entries 变成 `KnowledgeChunk`。chunk 必须引用单个 entry，并且 offset 相对于该 entry，因此不能在第二级简单拼接多个历史 entry；否则来源与 offset 会失真。

数学讲义的块公式通常使用以下结构：

```text
说明：

$$
公式
$$

结论。
```

旧解析会得到三个 entries，HIERARCHY 最终也产生三个很短的正文切片。根因是一级边界过细，不是 `$$` 字符需要从正文中删除。

## Goals

- 保留标题、解释、公式和结论组成的短章节，使其能够进入同一二级切片。
- 不把 fenced code 或块公式内部内容解释为 Markdown 标题或段落边界。
- 保持严格 UTF-8、1000 code points 的 entry 上限，以及二级切片的 800/自定义上限、重叠和 offset 语义。
- 不隐式重写历史知识条目。

## Decisions

### 1. 一级解析按 Markdown 块扫描并按章节装箱

`TextParser` 逐行扫描规范化后的文本。空行只结束当前 Markdown 块；进入反引号/波浪号代码围栏、`$$` 或 `\[` 公式围栏后，内部空行保留在同一块中，直到匹配的关闭定界符。

块按原顺序装入 entry：一级到三级 ATX 标题开启新 entry；同一标题后的普通段落、列表、公式和结论使用两个换行连接，只要合并结果不超过 1000 code points。加入下一块会超限时先提交当前 entry。单个块自身超过上限时才按 code point 硬切，因此不会拆开代理对。

标题是边界而不是被删除的元数据。HIERARCHY 可以读取它并合成标题路径，AUTO/CUSTOM 仍能检索到标题正文。纯文本文件没有标题时会按长度把相邻段落装箱，减少旧规则造成的极短 entries。

### 2. HIERARCHY 使用有状态的标题扫描

以逐行扫描替换跨全文的标题正则。扫描器跟踪与一级解析相同的代码/公式围栏状态，只在围栏外识别 `#`、`##`、`###`。每个标题仍记录 code point 起止位置，后续章节切分、标题栈和正文 offset 逻辑保持不变。

围栏未闭合时按材料余下内容都在围栏内处理，避免把不完整代码示例中的 `#` 进一步误判成标题。系统不尝试修复或执行 Markdown/LaTeX。

### 3. 历史数据显式重入库

索引重建继续只消费现有 `KnowledgeEntry`，不读取并覆盖原文件解析结果。这样保持失败边界和来源 ID 稳定，也避免在向量重建操作中引入正文事务。采用旧空行规则的材料要应用新算法，需删除后重新上传；本变更不增加新的“重解析 READY 材料”接口。

## Risks and Mitigations

- 合并段落会减少 entry 数量：二级窗口仍执行长度上限与优先断点，检索 chunk 不会无限增大。
- 非 Markdown 文本可能恰好以 `# ` 开头：这与现有 HIERARCHY 标题语义一致，只影响 entry 分组，不改写字符。
- 超长 fenced block 仍可能被硬切：1000 code points 是持久化上限，安全长度优先；正常长度围栏保持完整。
