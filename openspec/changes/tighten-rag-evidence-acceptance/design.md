# Design: 搜索宽召回与问答高精度采信分离

## Context

公开检索页面需要帮助用户浏览可能相关的片段，适合保留较宽召回；有依据问答一旦接受任一候选就会调用模型，因此更应优先降低误答。两者继续复用 keyword、vector 与 RRF 排序，但在最终用途上采用不同边界。

MySQL `MATCH ... AGAINST` 分数随查询和语料变化，RRF 分数也只由候选名次与 `k` 决定，二者都不适合作为固定语义置信度。向量余弦分数相对更适合作为经验门槛，但当前模型名是部署配置，未经人工标注集校准，因此本次只采用保守、可覆盖的起始值。

## Decisions

### 1. 问答使用两档向量门槛

问答候选满足以下任一条件才可进入模型上下文：

1. `vectorScore >= 0.55`，允许强向量候选单路通过；
2. 同一片段同时出现在 keyword 与 vector 结果中，且 `vectorScore >= 0.45`，用词法命中为中等向量相关性提供交叉确认。

关键词单路结果不直接采信。RRF 仍决定通过门槛的候选顺序，不增加固定 RRF 分数线。原 `0.35` 继续作为 Qdrant 宽召回门槛，便于直接检索和融合阶段保留候选。

两个新阈值通过环境配置覆盖，并要求 `0 <= vectorThreshold <= corroboratedThreshold <= strongThreshold <= 1`，错误配置在应用启动时失败。

### 2. 先采信过滤，再截取问答上限

keyword 与 vector 仍各自取得 `limit * 3` 个候选并执行标准 RRF。问答链路随后过滤不满足采信门的候选，再按原排序取最多 4 条，避免前四个弱候选遮挡后面的可采信片段。

`POST /api/retrieval/search` 不应用问答采信门，继续返回所选模式下的宽召回结果。`POST /api/ask` 与智能体绑定材料检索统一应用采信门；过滤后为空时沿用固定无依据分支，不连接 Chat。

### 3. 零文本重合不修复为引用

模型返回有效 `[n]` 时仍按首次出现顺序过滤和重编号。模型完全漏标时，既有二元字符重合启发式只在最高重合数大于零时补一条引用；所有候选重合数均为零时，最终内容改为“资料中未找到相关内容”，引用为空。

该规则不验证模型已经显式标注的事实蕴含关系；更强的逐事实校验或 reranker 不在本次范围。

## Risks and Mitigations

- 经验门槛可能拒绝部分真实相关片段：问答优先避免无依据生成，直接检索仍可展示宽召回结果；阈值保持可配置。
- 不同 embedding 模型分数分布不同：默认值只作为保守起点，未宣称完成数据集校准。
- 流式正文在收尾验证前已逐字发送：`done` 后页面以持久化消息为事实源，最终落库内容和引用必须采用拒答结果。
