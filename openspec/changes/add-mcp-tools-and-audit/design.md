# Design: MCP 工具接入、审计与问答集成

## Context

Class05 已建立班级隔离的智能体、技能文本、材料检索、流式会话和引用展示。当前实现中：

- `skills.tool_name` 是必填的单字符串，解析器只接受 `knowledge_search`；
- 会话准备阶段固定执行材料检索，检索为空便直接返回本地无依据答复；
- SSE `meta` 只有状态、技能名和材料引用；
- 会话结束后前端重新请求消息详情，因此只存在内存或 SSE 中的工具信息会被覆盖；
- 系统没有外部工具凭据存储、连接探测、调用审计和失败隔离边界。

本设计在这些既有约束上增加一个最小 MCP HTTP 子集。所有查询、配置和审计仍以服务端从 JWT 得到的 `class_id` 为边界，客户端提供的班级信息不参与授权。

## Goals

- 打通“登记服务 → 连接发现 → 技能引用 → 问答调用 → 前端展示 → 教师审计”的可演示闭环。
- 保持 Class05 材料检索、引用、会话恢复和失败消息行为兼容。
- 对外部网络、输出和凭据建立明确的超时、大小、过滤、日志和权限边界。
- 在并发修改、连接失败和删除竞争下保持服务状态、工具缓存与审计数据一致。

## Non-goals

- 完整实现 MCP 标准及其所有 transport/capability。
- 由大模型选择工具或生成任意参数。
- 工具调用重试、并行编排、长任务轮询或工具结果流式转发。
- 跨班级复用 MCP 服务或将原始工具响应永久保存。

## Decisions

### 1. MCP 服务采用独立 Python HTTP 容器

仓库新增 `mcp-server/`，使用 Python 3.13 标准库实现单进程 HTTP JSON-RPC 2.0 服务，避免为课程演示引入额外运行时依赖。服务暴露：

- `GET /health`：容器健康检查；
- `POST /mcp`：接收 JSON-RPC 2.0 请求；
- `initialize`：返回服务身份和支持能力；
- `tools/list`：返回工具名、说明和 JSON Schema；
- `tools/call`：执行指定工具并返回结构化结果。

服务至少提供两个确定性工具：`formula_hint` 与 `unit_convert`。`tools/call` 使用 `{content:[{type:"text",text:"..."}],isError:false}` 形状返回文本结果，业务错误使用 `isError:true`，协议错误使用 JSON-RPC error。工具名必须匹配 `[a-z][a-z0-9_]{0,31}`。除健康检查外的请求必须携带 `Authorization: Bearer <MCP_AUTH_TOKEN>`；缺少或错误凭据统一返回 `401`，日志不得输出 Token。

Compose 通过内部服务名访问 MCP 服务，并用环境变量注入 Token。CampusClaw 允许登记 `http` 或 `https` 地址，也允许 Compose 内网主机名；禁止 URL 中的用户信息、查询串和片段，统一规范化为以 `/mcp` 结尾的地址，并禁止跟随重定向。目标主机必须精确匹配环境变量 `MCP_ALLOWED_HOSTS` 中的主机名或 IP；默认开发配置只允许 `mcp-demo`，端口仍由登记地址显式给出，从而避免教师配置被用作任意出站请求。

### 2. 班级级服务、缓存、审计和消息快照分开存储

数据库 V6 增加：

- `mcp_servers`：`class_id`、班级内唯一 `name`、`base_url`、仅服务端可读的 `auth_token_ciphertext`、连接状态、连接时间、配置版本和时间戳；
- `mcp_tools`：所属服务、工具名、说明、输入 Schema JSON 和时间戳，服务内工具名唯一；
- `mcp_tool_calls`：班级、服务、调用用户、可空的会话 ID、完整工具引用、`ok|denied|error` 状态、安全摘要和时间戳；
- `messages.tool_calls_json`：面向会话重载的安全调用快照，不保存 Token、Base URL、参数原文或原始错误栈。

`mcp_tool_calls.server_id` 使用限制删除的外键。`conversation_id` 只存审计关联值而不建立级联外键，使用户删除会话时教师审计仍可保留。删除服务前应用层先查审计；有记录返回 `409 Conflict`。并发竞争最终由限制删除外键兜底并映射为同样的 `409`。没有审计时可删除服务，`mcp_tools` 随服务级联删除。

服务名匹配 `[a-z][a-z0-9_-]{0,31}`，因此实际长度上限为 32；Base URL 上限 512，Token 上限 512。Token 使用应用层 AES-256-GCM 加密后落库：`MCP_TOKEN_ENCRYPTION_KEY` 必须是 Base64 编码的 32 字节密钥，每次写入使用随机 12 字节 IV，字段保存版本化的 `v1:<base64(iv+ciphertext+tag)>` 信封。密钥缺失或非法时应用启动失败；解密失败不得尝试连接，并返回脱敏的 HTTP 503。本次不包含密钥轮换，README 必须说明轮换前需先重新加密现有凭据。API DTO 永不包含密文或明文 Token，只返回 `hasAuth`；更新请求中的空 Token 表示保留旧值。

### 3. 连接探测不持有数据库长事务

连接流程分三段：

1. 短事务读取服务配置、配置版本与 Token 快照；
2. 事务外依次执行 `initialize` 和 `tools/list`，使用 `MCP_CONNECT_TIMEOUT`（默认 3 秒）和 `MCP_READ_TIMEOUT`（默认 10 秒），并完整校验响应和所有工具定义；
3. 短事务重新读取配置版本。版本一致时一次性替换工具缓存并标记已连接；版本变化时丢弃探测结果并返回 `409`。

修改名称、地址或 Token 都会递增配置版本、标记断开并清空工具缓存，要求教师重新连接。任何连接超时、HTTP 非成功、协议错误或非法工具清单都会使服务保持断开并清空旧缓存，API 返回不包含远端细节的 `502`；本地数据库不可用返回 `503`。连接和工具调用均不自动重试，避免重复副作用。

选择“先完整校验，再整体替换”，而不是边接收边写入，避免半份工具清单被技能引用。

### 4. 技能存储升级为规范化的多工具引用

V6 将 `skills.tool_name` 迁移为 `tool_refs TEXT NOT NULL`，保存规范化后的逗号分隔引用：

- 内置引用：`knowledge_search`；
- MCP 引用：`工具名@服务名`；
- 支持输入中英文逗号、顿号、分号、竖线或换行分隔；
- 按首次出现顺序去重；单条引用和总文本均有长度上限，总长度不超过 8,000 字符。

迁移把现有 `tool_name` 原值写入 `tool_refs` 后再删除旧列，因此所有 Class05 技能继续包含 `knowledge_search`。领域模型和接口使用 `toolRefs` 列表，避免继续暴露“只能单选”的语义。

技能保存先完成纯语法解析，再在事务中校验所有 MCP 引用都属于当前 JWT 班级、服务已连接且工具存在于最新缓存。不存在、跨班级、未连接或未发现统一返回 `400` 和不泄露资源存在性的“工具不可用”消息；整次保存回滚。`knowledge_search` 是兼容用的内置标记，不通过 MCP 调度，也不改变现有“绑定材料后执行检索”的 Class05 行为。

服务重命名不会自动改写已有技能正文或引用。因为更新会使服务断开并清空缓存，旧引用在后续调用时自然成为不可用引用，教师需要显式修改技能，避免隐藏的大范围配置改写。

### 5. 工具按技能顺序串行调用，失败与主问答隔离

只对本次选中的技能解析 MCP 引用，按规范化顺序串行调用，跳过 `knowledge_search`。本次不使用模型函数调用：后端通过明确的工具适配器构造参数。`formula_hint` 接收去除首尾空白、最多 500 个 Unicode code point 的 `{query: 当前问题}`；`unit_convert` 只接受从当前问题中匹配到的“数值 + 源单位 + `to|转|转换为` + 目标单位”，单位白名单为 `mm|cm|m|km|g|kg`，并构造 `{value,fromUnit,toUnit}`。未匹配、跨维度换算、未实现适配器或参数不合法按 `denied` 处理。

材料检索按 Class05 规则完成后，再执行工具调用；二者均在首个 SSE `meta` 前完成。每个引用独立产生安全的调用摘要：

- `ok`：服务存在且连接，远端成功返回可解析结果；
- `denied`：服务存在但断开、适配器拒绝或调用前策略不允许；此时写审计；
- `error`：超时、非成功 HTTP、JSON-RPC 错误、非法响应或远端工具错误；此时写审计；
- 服务/工具因删除、重命名或缓存变化已不存在时返回 `denied` 摘要，但因没有合法 `server_id` 不创建审计记录。

单个调用失败不会终止后续工具或主问答。不会自动重试。同一次请求可产生多个审计记录；`ok` 审计只保存过滤后结果的前 200 个 Unicode code point，`denied|error` 保存固定或脱敏原因，所有 `detail` 最多 512 个 Unicode code point，且不保存完整参数、原始响应、Token 或异常栈。

### 6. 外部输出经过长度与注入过滤后才可进入模型上下文

工具响应先提取文本，再限制为最多 1,200 个 Unicode code point。过滤器对常见指令注入模式做大小写无关检测，包括“忽略前述/此前指令”、“ignore previous instructions”、“你现在是”和伪造的 `system:` 前缀。命中时整段内容替换为固定安全提示，并标记为“不可用于生成”；不把危险片段截短后继续使用。

安全工具结果以带有服务和工具来源标签的“用户提供数据”区块加入 Chat 上下文，绝不拼接到 system prompt。工具状态可以是 `ok`，但经安全过滤后的结果仍可能不可用；“是否调用模型”依据可用结果而不是远端状态。

该过滤只为课程场景提供最小防线，不能证明任意第三方输出安全，因此还同时依赖固定提示词边界、大小限制、无模型自主选工具和不暴露凭据。

### 7. 材料证据和工具证据共同决定是否调用 Chat

准备阶段先完成材料检索和 MCP 调用，再按下列矩阵决定生成路径：

| 材料引用 | 安全可用工具结果 | 行为 |
| --- | --- | --- |
| 有 | 有 | 两类上下文共同调用 Chat |
| 有 | 无 | 仅材料上下文调用 Chat |
| 无 | 有 | 仅工具上下文调用 Chat，`citations=[]` |
| 无 | 无 | 不调用 Chat，返回既有固定无依据答复 |

仅工具结果生成时，现有引用标号过滤仍生效，模型不得伪造 `[n]` 材料引用。旧版 `/api/ask` 继续使用既有路径，不自动获得 MCP 调用能力。

### 8. `toolCalls` 同时进入 SSE meta 与持久化消息

扩展 SSE `meta` 为可选的 camelCase `toolCalls` 字段，元素仅含前端需要的工具引用、状态和安全摘要。所有工具调用在 `meta` 发送前结束，因此前端能在第一段正文前展示状态；所选技能没有 MCP 引用时省略该字段，保持旧客户端兼容。

流完成或失败时，安全调用摘要随助手消息写入 `messages.tool_calls_json`。会话详情 DTO 返回同一结构，使前端在 `done` 后重新加载和刷新页面时不会丢失工具状态。失败消息也保存已发生的调用摘要，但不会保存原始远端结果。

### 9. 管理界面沿用智能体配置页和既有权限模型

前端在 `/assistants` 页面增加教师可见的 MCP 区域，提供服务列表、新增/编辑、连接、工具列表、删除和审计列表；技能编辑器可选择已连接服务的已发现工具。Token 输入只用于提交，编辑时为空表示保留，界面不显示现有 Token。

学生不渲染管理入口；后端仍对所有写入、连接、工具查看和审计接口执行教师角色校验并返回 `403`。资源 ID 属于其他班级或不存在统一返回 `404`。审计列表默认 50 条、最大 100 条，按时间倒序，仅返回当前教师班级数据。

### 10. OpenAPI 和回归脚本作为契约入口

现有 Springdoc 页面继续位于 `/swagger-ui/index.html`，MCP 管理 DTO、错误码和 SSE `toolCalls` Schema 必须可从 `/v3/api-docs` 查看。API 回归脚本在原有 Class05 流程上增加教师配置、连接、技能绑定、对话调用、审计验证，以及学生、跨班级、断开、注入过滤和删除冲突场景。

## Error Mapping

| 场景 | HTTP / SSE 结果 |
| --- | --- |
| 未登录 | `401` |
| 学生访问 MCP 管理 | `403` |
| 服务 ID 不存在或跨班级 | `404` |
| 名称重复、URL/技能引用非法 | `400`；名称并发唯一键冲突同样映射 `400` |
| 连接期间配置发生变化 | `409` |
| 服务存在审计，禁止删除 | `409` |
| MCP 网络或协议失败 | 连接接口 `502`；对话中记录 `error` 并继续 |
| 本地数据库不可用 | `503` 或既有流式失败语义 |

## Security

- `class_id` 与角色只从认证上下文取得；所有仓储查询带班级条件。
- Token 只以 AES-256-GCM 密文写入数据库，解密后的短生命周期值只进入出站 Authorization，不进入 DTO、日志、异常、SSE、审计或消息快照；加密密钥只来自环境变量。
- URL 校验阻止凭据、查询和片段，并以 `MCP_ALLOWED_HOSTS` 精确限制目标主机；HTTP 客户端不跟随重定向，部署环境应进一步通过网络策略限制可达目标。
- 远端 Schema、说明、结果和错误全部视为不可信并限制长度；只有白名单字段返回前端。
- 工具结果只能作为数据进入 user context，不能覆盖 system prompt。
- 审计写入失败不能伪装成成功调用；调用摘要标记为 `error`，主问答仍按剩余可信证据继续。

## Consistency and Failure Recovery

- 连接发现以配置版本防止旧网络响应覆盖新配置。
- 工具缓存采用事务内整体替换，失败时为空且服务断开。
- 技能保存的全部引用在同一事务校验，避免部分保存。
- 每个远端调用最多写一条审计，无自动重试；消息快照与助手消息同事务保存。
- 断开或修改配置会主动清空缓存；对话调用前仍重新检查连接状态和工具存在性，处理配置后的并发窗口。

## Migration and Rollback

1. V6 先创建 MCP 三张表和 `messages.tool_calls_json`。
2. 为 `skills` 增加可空 `tool_refs`，从 `tool_name` 回填并校验非空。
3. 将 `tool_refs` 改为非空并删除 `tool_name`。
4. 发布后旧技能继续以 `knowledge_search` 工作，新字段为空的历史消息按无工具摘要处理。

回滚应用版本前必须先执行显式的向下迁移：从 `tool_refs` 选择首个兼容值回填 `tool_name`。若技能已配置多个 MCP 引用，该回滚是有损的，因此生产回滚前必须导出技能正文和 MCP 配置。MCP 容器可独立停用；后端未登记服务时不影响 Class05 路径。

## Alternatives Considered

- **使用完整 MCP SDK**：当前课程只需固定 HTTP 子集，引入完整 SDK 会增加协议和依赖面，暂不采用。
- **将工具响应仅保存在 SSE**：`done` 后现有前端会重载消息并丢失信息，因此采用消息快照。
- **有审计时级联删除**：会破坏追溯性，改为明确 `409` 并建议断开服务。
- **工具失败即终止回答**：会降低原有材料问答可用性，改为逐工具隔离并继续使用剩余证据。
- **仅材料存在才调用 Chat**：无法支持 Class06 的工具独立价值，改为材料或安全工具结果任一可触发生成。
- **服务改名时自动重写技能**：会造成隐藏的跨对象批量变更，改为显式修改技能。

## Resolved Contract Decisions

- 安全可用的工具结果可以单独支撑 Chat 生成；此时材料引用为空，来源由 `toolCalls` 表达。
- 服务一旦存在审计便不可删除，返回 `409`；教师可以断开它。无审计服务可删除并级联清理工具缓存。
- JSON 字段统一使用 `toolCalls`，与当前 DTO 的 camelCase 序列化风格一致。
- 调用不自动重试；消息持久化保存安全摘要，以支持会话重载。
