# Change: 接入 MCP 工具、调用审计与对话可视化

## Why

当前技能配置只能保存单个 `tool_name`，解析器也只接受内置标记 `knowledge_search`。系统尚不能登记外部工具服务、发现工具、在问答前调用工具，也无法让教师追踪调用结果。这使 Class06 要求的“工具服务—技能引用—问答调用—审计与展示”链路无法成立。

本次变更要在不破坏 Class05 材料检索与流式问答的前提下，引入一个边界清晰、可审计的 MCP 子集。外部工具输出必须被视为不可信数据；工具不可用时不得拖垮原有问答；仅有安全可用的工具结果时，也允许模型生成回答。

## What Changes

- 在仓库中新增独立 `mcp-server` 服务，通过 HTTP JSON-RPC 2.0 提供 `initialize`、`tools/list`、`tools/call`，并内置至少两个真实可调用工具。
- 在 Compose 中接入 MCP 服务，使用独立 Bearer Token、健康检查和内部网络地址；CampusClaw 后端加密保存凭据，任何响应均不回传明文 Token。
- 新增班级级 MCP 服务管理、连接探测、工具发现与缓存能力；教师可增删改查、连接和查看工具，学生无权管理。
- 新增 MCP 工具调用审计。审计存在时禁止删除对应服务并返回 `409`；无审计时允许删除并级联清理工具缓存。
- 将技能的单一工具字段升级为有序、去重的多工具引用，兼容内置 `knowledge_search`，并支持 `工具名@服务名`。
- 在流式问答准备阶段按技能配置顺序调用 MCP 工具，限制超时、长度和指令注入内容；单个工具失败只记录状态，不中止主问答。
- 调整证据判定：材料引用或安全可用的工具结果任一存在即可调用 Chat；二者均不存在时才返回固定无依据答复。
- 扩展 SSE `meta` 和消息快照，增加可选的 `toolCalls`；前端在正文前展示工具调用来源与状态，并能在重新载入会话后恢复。
- 在现有智能体配置页增加 MCP 管理区域，并扩展 OpenAPI 与 API 回归脚本覆盖完整链路。

## Capabilities

### New Capabilities

- `mcp-tool-integration`：MCP 服务生命周期、工具发现、调用边界、安全过滤、审计和教师管理接口。

### Modified Capabilities

- `agent-configuration`：技能支持有序的多工具引用，并在保存时校验本班级可用工具。
- `conversation-streaming`：问答准备阶段调用技能工具，合并材料与工具上下文，并通过 SSE 和消息详情暴露安全调用摘要。
- `api-regression-harness`：覆盖 MCP 服务管理、技能绑定、流式调用、审计和权限隔离。

## Impact

- 数据库新增 `mcp_servers`、`mcp_tools`、`mcp_tool_calls`，升级 `skills` 工具字段，并为 `messages` 增加工具调用快照字段。
- 后端新增 MCP 管理、协议客户端、工具调度、安全过滤和审计模块；现有问答准备流程和消息持久化流程会被扩展。
- 前端修改智能体配置页、技能编辑器和对话消息展示，但保持现有路由与整体视觉结构。
- 部署增加一个容器、Token、Token 加密密钥、允许访问的 MCP 主机列表以及连接/读取超时配置。
- 现有 Class05 数据需要迁移；`knowledge_search`、材料引用、SSE 文本事件和 `/api/ask` 行为继续兼容。

## Non-goals

- 不实现完整 MCP SDK、stdio/SSE transport、服务端推送、资源或提示词协议。
- 不让模型自主选择工具，也不实现模型生成工具参数、并行调用或自动重试。
- 不提供公共 MCP 市场、跨班级共享服务、学生管理入口或密钥查看功能。
- 不把外部工具结果当作系统指令，也不承诺对任意第三方工具输出做通用语义清洗。
- 不改变现有知识材料上传、向量检索、引用标号规则或旧版 `/api/ask` 接口。
